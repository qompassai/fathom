# inbox: fathom-il2cpp Stage A (2026-10-20)

Finding (validated on primo, branch pax/fathom-il2cpp-20261019):
fathom-native gained an `il2cpp` module: three tools (provider
`ghidra-il2cpp`) that apply an Il2CppDumper script.json map to a
Ghidra project copy and query it, via Java GhidraScripts under
analyzeHeadless — never PyGhidra (its interactive venv installer
is what killed the first Stage A probe).

- il2cpp_apply (Execute class): names functions from the map
  (first name at an address wins; shared addresses become
  labels), applies signatures as plate comments and string
  literals as EOL comments. Idempotent.
- il2cpp_decompile / il2cpp_xrefs (Read class): decompile one
  method with depth-1 callees; xref census with callers
  classified engine / third-party / game / unknown.

Acceptance on the target dump (159,716 methods): 158,539 names
kept, 86,511 functions renamed, 5,311 string literals applied;
workspace 156 tests pass (baseline 147). Analysis write-ups in
~/fathom-stageA/ (LIFT-la-load.md, XREFS.md, REPORT.md).

Reusable pattern: IL2CPP string-vault classes generated by
protectors store strings as one masked byte[] in the metadata
(unmask: plain[i] = stored[i] ^ (i mod 256) ^ 0xAA) with lazy
(index, offset, length) getters; the slices are plain UTF-8.
